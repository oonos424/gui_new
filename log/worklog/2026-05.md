# WorkLog — May 2026

## 2026-05-07 — Main window scaffold

### What was done

Implemented the minimum application bootstrap needed for `./gradlew run` to open a window:

- **Gradle wrapper** bootstrapped (copied from reference `affrgui` project; updated to Gradle 9.0)
- **`affr.app.AFFrMain`** — JavaFX `Application` entry point
- **`affr.app.AppConfig`** — immutable record for CLI args (`--profile`, `--tutorial-dir`); parsed manually without picocli to avoid Checker Framework noise
- **`affr.app.NavigationService`** — loads screen FXMLs and swaps the Stage's scene
- **`affr.app.top.TopCategory`** — enum for the three Project Browser navigation modes
- **`affr.app.top.TopController`** + `TopController.fxml` + `top.css` — Project Browser screen shell (HEADER / MANAGER / VIEWER layout per spec)
- **`javafx.astub`** extended with `FXMLLoader` stubs

### Decisions

- **Gradle 9.0** instead of 8.14.2 — Gradle 8.14.x bundles Kotlin 2.0.21 which cannot parse the Java 25.0.3 version string; Gradle 9.0 bundles Kotlin 2.2 which fixes this.
- **Kotlin 2.2.0** instead of 1.9.25 — needed to avoid "Unknown Kotlin JVM target: 25"; Kotlin JVM target set to 24 (JVM 25 runs JVM 24 bytecode without issue; update when Kotlin adds JVM 25 target support).
- **Shadow plugin removed** — version 8.1.1 is not Gradle 9.0-compatible; packaging is deferred.
- **Configuration cache disabled** — Checker Framework plugin not yet verified compatible with Gradle 9.0 config cache; re-enable when plugins are updated.
- **FXML files co-located with Java source** — per spec; `processResources` copies them into resources at build time.
- **AppConfig parses args manually** — avoids picocli/Checker Framework annotation noise for 2 simple options; switch to picocli when CLI becomes more complex.

### Open questions

- Confirm Checker Framework 3.51.0 produces no false positives on the new source files.
- Investigate Checker Framework Gradle plugin (0.6.59) compatibility with Gradle 9.0 config cache.
- Kotlin JVM 25 target: monitor Kotlin releases; update `kotlinJvmTarget` in `build.gradle.kts` when support is added.

## 2026-05-07 — Initial project scaffold (gui_new)

### What was done
Created the `gui_new` repository from scratch with the full build toolchain, adapted from
the existing `affrgui` reference project and the spec at `affrgui_spec/`.

### Decisions
- **Java 25 / JavaFX 25** instead of 21 — matches the to-be target in the spec.
- **VTK Java wrapper removed** — 3D viewer moves to Python/Trame subprocess accessed via JavaFX `WebView`; `javafx.swing` module excluded accordingly.
- **`temurin:25` / `liberica:25`** added as primary JVM candidates in `JavaEnv.bash` / `JavaEnv.ps1`; 21 kept as fallback.
- **Monaco resource path** changed from `jp.advancesoft.*` to `affr/app/editor/monaco/vs` to match the new package namespace.
- **FXML formatter** updated to `--jfx-version=25.0`; pre-commit Java/Kotlin formatters updated to `--jvm=temurin:25`.
- **Launch4j / JDK download tasks omitted** from `build.gradle.kts` for now — packaging is not the immediate concern; will be added when the build is stable.

### Open questions
- `org.testfx:openjfx-monocle:21.0.2` is pinned to JavaFX 21 — no JavaFX 25 release confirmed yet. May need substitution or a workaround for headless CI tests.
- `trame_backend/` directory created but not yet populated.

### Notes for future sessions
- Gradle wrapper (`gradle/wrapper/`), placeholder `AFFrMain.java`, and `src/main/astub/javafx.astub` still need to be written before `./gradlew run` will work.
- Run `./setup` (requires `uv` on PATH) after the wrapper is in place to install pre-commit hooks.
- `rxjavafx 2.0.2` uses group `io.reactivex` (not `io.reactivex.rxjava2`) — this is intentional and matches the reference project.
